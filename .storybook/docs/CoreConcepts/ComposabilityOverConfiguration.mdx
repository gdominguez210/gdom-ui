# Composability Over Configuration

GDOM-UI follows a compositional architecture that prioritizes flexible building blocks over complex configuration options. This approach empowers developers to create precisely what they need by combining specialized components.

## The Composition Advantage

Rather than creating monolithic components with extensive configuration props, GDOM-UI provides focused components that can be composed to build complex interfaces.

A configuration-heavy approach often leads to numerous props to manage feature visibility:

<Source
  language="tsx"
  dark
  code={`
<ComplexAudioPlayer
  showProgressBar={true}
  showTitle={true}
  showArtwork={false}
  showVolumeControl={true}
  progressBarPosition="top"
  volumeControlType="slider"
  playButtonSize="large"
  // Many more configuration props...
/>
`}
/>

GDOM-UI instead uses composition to include only what you need, arranged exactly how you want:

<Source
  language="tsx"
  dark
  code={`
<AudioPlayer.Provider tracks={tracks}>
  <div className="flex flex-col space-y-4">
    <AudioPlayer.ProgressBar className="w-full" />
    <div className="flex items-center justify-between">
      <div>
        <AudioPlayer.Title className="text-lg font-bold" />
        <AudioPlayer.Author className="text-sm text-gray-600" />
      </div>
      <div className="flex items-center gap-2">
        <AudioPlayer.ControlPrevious />
        <AudioPlayer.ControlPlay size="large" />
        <AudioPlayer.ControlNext />
        <AudioPlayer.Volume />
      </div>
    </div>
  </div>
</AudioPlayer.Provider>
`}
/>

## Key Benefits

This compositional approach offers several significant advantages:

- **Precise Control**: Build exactly what you need with full control over layout, styling, and functionality
- **Bundle Optimization**: Only components you actually use are included in your bundle
- **Flexible Styling**: Position and style each component independently using your preferred approach
- **Maintainable Code**: Smaller, focused components are easier to understand, test, and maintain
- **Progressive Complexity**: Simple use cases remain simple, while complex scenarios are still possible
- **Custom Integrations**: Easily mix GDOM-UI components with your own custom components

For details on how state is shared between components in the component architecture, see [Two-Tier Components](/docs/core-concepts-two-tier-components--docs).
